# 61 保护与充电联锁

## 1. 数据流

```text
充电请求
  │
  ├─ 运行前：ProtectionController.update(t=0, 初始单体电压, I=0, T)
  │     ├─ charge_allowed=False → 拒绝运行，记录原因
  │     └─ charge_allowed=True  → 继续
  │
  ├─ 真实 ngspice 求解（20 ns）
  │
  └─ 运行后：每 20 个采样点回灌真实波形
        ├─ 首次撤销许可时间
        ├─ 锁存故障集合
        └─ 同时做 PWM 周期平均的原始限值核查
```

C01 回灌点数 20981（8 ms / 20 ns / 20），说明回灌覆盖了整个窗口，
不是抽样检查。

## 2. 保护阈值未被修改

`protection.limits.load_limits()` 在第六阶段原样复用第五阶段配置：

| 项 | 触发 | 释放 |
| --- | --- | --- |
| 单体过压 | 4.25 V | 4.15 V |
| 单体欠压 | 2.80 V | 3.00 V |
| 充电过流 | 1.50 A | 1.30 A |
| 放电过流 | 4.00 A | 3.50 A |
| 短路 | 8.00 A | — |
| 过温 | 65 ℃ | 55 ℃ |
| 充电温度窗 | 0–45 ℃ | — |
| 故障全清 | 5 s 稳定 | — |
| 自动重启 | 禁止 | — |

充电恒压 12.15 V 折合 4.05 V/节，低于过压释放 4.15 V；恒流 1.0 A 低于充电过流
1.50 A。两个余量由 `ChargerConfig.validate_against_protection()` 强制检查。

## 4. 两个必须保留的负结果

### 4.1 恒压目标下"不一致导致过压"不成立

恒压 12.15 V 把组压限制在 4.05 V/节附近。即使 SOC 极差 0.40（C11 的注入条件），
在正常恒压调节下最高单体也只到约 4.16–4.19 V（C18 为 4.1844 V），
**达不到 4.25 V 触发阈值**。因此：

- C11 必须在 CC-only 故障注入下才能演示"单体先于组端 CV 过压"；
- 不能把 C11 的结论表述为"正常充电中不一致会触发过压"；
- 若产品需要覆盖该风险，应降低单体过压阈值、增加均衡，或在 CV 目标上留更大
  的单体余量（属于设计选择，不在本阶段改动）。

### 4.2 短窗不能证明保护不会动作

开关级工况只有 8–12 ms，而多数保护确认延时为 150 ms–5 s。因此：

- "窗口内未锁存"只说明窗口内未锁存；
- 真实保护动作需要长时模型（C11 的 293.5 s）或软件测试（C12/C13/C15/C17）；
- 两类证据必须分开陈述。
