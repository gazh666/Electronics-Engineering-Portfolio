# 89 硬件验证计划

本文件定义第八阶段之后的 15 项硬件验证。**全部项目前为 `NOT_EXECUTED`**：没有制板、
没有装配、没有上电、没有测量。本文件只写设备类别、工况、指标与风险，不包含任何实测数据。

`pytest tests -q` 为 412 passed，第八阶段新增 68 个测试全部通过。测试通过不等于硬件验证。

安全前提：

## 3. 分阶段执行顺序

| 阶段 | 项目 | 前置条件 | 失败即停止 |
| --- | --- | --- | --- |
| A 静态 | V01、V02 | 板已装配 | 是 |
| B 上电 | V03、V04 | A 通过，限流电源就绪 | 是 |
| C 采集 | V05、V06、V07 | B 通过，模拟器校准 | 是 |
| D 功率 | V08、V09 | C 通过，负载与热像仪就绪 | 是 |
| E 充电 | V10、V11 | D 通过，电池模拟器就绪 | 是 |
| F 系统 | V12、V13、V14 | E 通过 | 视情况 |
| G 交接 | V15 | 以上记录齐全 | 否 |

顺序的理由：先确认没有装配错误，再确认电源轨，再确认采集，最后才给功率级上电。
跳步会把装配错误放大成器件损坏。

## 4. 关键验证项细节

### V03 电源轨

| 项 | 内容 |
| --- | --- |
| 目的 | 确认 BAT、REG18、REG1 3.3 V 正常 |
| 工况 | 9.0 / 11.1 / 12.6 V，限流 100 mA |
| 指标 | REG18 1.6–2.0 V；REG1 3.0–3.6 V；静态电流在数据手册量级 |
| 记录 | 每个电压点的输入电流、各路电压、温度 |
| 风险 | 电源轨异常会直接损坏 AFE，必须先限流 |

### V05 单体电压精度

数据手册目标是 ±5 mV（25 ℃），本计划放宽到 ≤±10 mV 作为板级验收线，原因是分压与
滤波会引入系统误差。必须在 25 ℃ 恒温、四通道独立可编程条件下逐点扫描并记录温度；
超标时先分离 AFE 误差与板级误差，不能一句"芯片不准"带过。

### V06 双向电流精度

分流电阻 10 mΩ，2.5 A 对应 25 mV。零点校准后失调 ≤2 mA、增益误差 ≤0.5% 是本计划的
目标值，不是数据手册保证值。必须四线制测量，并把 Kelvin 走线错误与焊点虚接列为
首要排查项。

### V10 CC-CV 充电

| 项 | 目标 | 说明 |
| --- | --- | --- |
| 恒流 | 1.006 A（设计值） | 验收 ±3% |
| 恒压 | 12.075 V（设计值） | 验收 ±0.5% |
| 终止 | 0.1012 A | 与预充同式 |
| 定时 | 5.227 h | 56 nF |
| 输入 | 18 V | 限流 1.5 A |

恒压点必须用六位半表在电池端测量，不能用电源读数代替。若恒压偏离，先查分压电阻与
VFB 漏电，再查芯片基准。

## 5. 判定规则与证据要求

| 规则 | 要求 |
| --- | --- |
| 限值预登记 | 测试前写入配置，测试后不得修改 |
| Run ID | 每次测试独立目录，禁止复用旧数据 |
| 仪器记录 | 型号、序列号、校准有效期 |
| 原始数据 | 保留原始波形/读数，不只保留结论 |
| 失败保留 | 失败就是失败，不能删除或改写 |
| 估算与实测分离 | 计算值不得填入实测列 |
| 仿真与实测分离 | ngspice/PyBaMM 结果不得标为硬件实测 |
| 状态机 | NOT_EXECUTED → PASS/FAIL 只能由真实数据触发 |

`NOT_EXECUTED` 不是"待定通过"，也不是"默认通过"。没有数据时，唯一正确的状态就是
`NOT_EXECUTED`。

## 6. 安全边界

| 风险 | 控制措施 |
| --- | --- |
| 反接 | 输入端反向阻断 PFET、防反接夹具 |
| 过流 | 电源限流、保险丝、电子负载限流 |
| 过温 | 热像仪监控、热电偶、超温立即断电 |
| 短路 | 受控短路测试，毫秒级切断，禁止真实电芯 |
| 高压 | 输入不超过 19 V；ACOV 32 V 只作为保护讨论，不做破坏性验证 |
| 滥用 | 不做过充、针刺、挤压、真实电芯短路 |

测试对象是电芯模拟器与电子负载，不是真实锂电池。任何需要"真实电芯"的滥用项都不在
本计划内。

## 7. TestLab 复用

| 项 | 做法 |
| --- | --- |
| 复用范围 | SCPI 仪器控制、虚拟仪器、数据落盘 |
| 不复用 | 不修改 TestLab 代码与环境，不共享可变状态 |
| 接口 | 通过 SCPI 读取电压/电流/温度，写入本项目 Run ID |
| 同步 | 记录仪器时基与采样率，避免"时间戳对齐"假象 |
| 可复现 | 每条结论附命令、配置与原始数据路径 |

复用 TestLab 是复用测量能力，不是复用历史结论。其他项目的通过记录不能迁移到本设计。

## 8. 与第九阶段的接口

1. 网表、BOM、引脚映射与 `design_calculations.json` 可被第九阶段直接读取。
2. 所有状态字段保持 `NOT_EXECUTED` / `BLOCKED`，第九阶段不得改写成通过。
3. 真实硬件数据产生后，新增 Run ID，以实测值替换估算值，同时保留本文件作为基线。
4. 任何设计变更（电感、电容、反馈电阻、MOSFET）都必须重跑相关验证项，不能沿用旧结论。
5. 阶段交接以 `release_manifest.json` 的哈希为准，确保文件未被替换。

## 9. 本文件不能支持的结论

- 不能声称"已验证 15 项"或"全部通过"。
- 不能把设计计算值写进"实测"列。
- 不能把第七阶段的仿真充电曲线当作本板的 CC-CV 实测。
- 不能因为"预期会通过"就提前把状态改为 PASS。

## 自测题

**1. 为什么本文件所有验证项都是 NOT_EXECUTED？**

要点：未制板、未装配、未上电、无测量设备数据；本阶段纪律禁止采购、制板与上电。

**2. 15 项验证的执行顺序为什么先静态、再电源轨、最后功率？**

要点：先排除装配错误，再确认电源轨，再验证采集，最后给功率级上电，避免把错误放大成器件损坏。

**3. V05 的验收线为什么是 ±10 mV 而不是数据手册的 ±5 mV？**

要点：±5 mV 是芯片 25 ℃ 指标；板级分压与滤波会引入系统误差，因此板级验收放宽到 ±10 mV并记录温度。

**4. 仿真或计算结果能不能填入实测列？**

要点：不能。计算、仿真、实测是三套证据，必须分开记录；NOT_EXECUTED 不能变 PASS。

**5. 第九阶段复用本阶段材料时，哪些字段不能改？**

要点：状态字段（NOT_EXECUTED/BLOCKED）与基线数据不能改；新增实测应使用新 Run ID，并保留原基线。
