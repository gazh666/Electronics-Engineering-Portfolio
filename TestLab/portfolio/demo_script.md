```powershell
cd TestLab
& "C:\\Users\\<user>\.conda\envs\kaifa\python.exe" -m pip check

```

确认：

- `results/automation/` 有历史运行；
- `assets/screenshots/` 有两张真实截图；
- 浏览器已打开 `http://127.0.0.1:8501`（提前启动）。

## 第 1 步（0:00–0:45）项目定位

- 话术：“这是一个基于 PyVISA-sim 的虚拟工业测试平台。它不只是读数，
  而是把测试用例、判定、异常处理、历史与报告串成闭环。”
- 展示：README 顶部状态表 + 数据来源表。
- 不要展示：任何“真实硬件”措辞。

## 第 2 步（0:45–2:00）运行概览与自动化

- 操作：Web 首页 → 自动化测试页 → 选择 `SUITE-SMOKE` → 执行。
- 话术：“执行只在按钮分支发生；任务串行锁保证不会并发占用仪器；
  进度在结果落盘后才推进。”
- 观察：PASS/FAIL/ERROR/SKIP 汇总、运行编号、耗时。
- 备选：若现场不便执行，打开历史页选择已有 `SUITE005` 运行。

## 第 3 步（2:00–3:00）运行详情与配置快照

  指标与数据来源；快照来自运行当时，不是当前配置。”
- 强调：设置值必须与回读一致才允许测量。

## 第 4 步（3:00–4:30）可靠性验证

- 操作：可靠性页选择 F001（通信超时）执行；或命令行：
  ```powershell
  python -m scripts.fault_injection_demo --scenario F001
  ```
- 话术：“故障是确定性的，不是随机；只重试只读查询且分类为瞬态通信；

## 常见提问与回答

| 提问 | 回答 |
| --- | --- |
| 这是真实硬件吗？ | 不是，全部为 PyVISA-sim + 行为模型。 |
| 为什么不用真仪器？ | 成本与安全；模拟足以验证测试架构。 |
| 效率 90% 可信吗？ | 是预设模型参数，不是实测。 |
| 为什么不做纹波？ | 模型没有时间序列，不能伪造。 |
| Docker 跑过吗？ | 没有，本机未安装，标记 NOT_VERIFIED。 |
| 覆盖率为什么不是 100%？ | 交互与极端 IO 分支成本高，未覆盖原因已记录。 |

## 失败兜底

- Web 启动失败：改用命令行 `scripts.run_test_suite` + 展示已有报告；
- 端口占用：换 `--server.port 8502`；
- 报告生成失败：展示 `docs/30` 验收输出与已有 HTML；
- 测试环境异常：不现场修复，直接展示 `docs/29` 的真实结果并说明。
