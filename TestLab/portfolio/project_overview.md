# TestLab 项目总览

## 1. 一句话介绍

TestLab 是一个基于 PyVISA-sim 的工业自动化测试与虚拟仪器平台：用虚拟电源、
万用表、电子负载和 12 V→5 V DC-DC 行为模型，完成电源类产品的自动化测试、
工程指标计算、PASS/FAIL 判定、故障注入、可靠性验证、SQLite 历史管理与
可打印综合报告。

## 2. 项目背景

学习与求职中常见的“仪器控制”项目往往停留在“能连上仪器、读一个数”，
缺少工业测试真正需要的部分：

- 测试用例与方案如何组织；
- 设置值是否真的写入仪器；
- PASS/FAIL/ERROR/SKIP 如何判定与汇总；
- 通信失败、非法响应、超时如何处理；
- 测试中断或清理失败后如何保证安全；
- 结果如何持久化、追溯、导出报告；
- Web 页面刷新是否会重复执行昂贵测试；
- 工程化交付（依赖、路径、备份、部署、CI）是否完整。

TestLab 逐阶段补上这些能力，并保持“模拟环境”与“真实硬件”的边界清晰。

## 3. 系统组成

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 界面层 | `app.py`、`ui/` | 六页 Streamlit 平台、服务层调用、状态保持 |
| 服务层 | `ui/service.py` | 唯一 Web 入口、任务串行锁、进度、汇总、导出 |
| 编排层 | `engine/` | 用例/方案加载、执行、判定、故障与重试集成 |
| 可靠性 | `reliability/` | 故障场景、异常分类、重试策略、事件、统计 |
| 测试台 | `bench/` | 读取仪器设置、调用模型、组装带来源标签的测量 |
| 模型层 | `models/virtual_dut.py` | DC-DC 稳态行为模型与保护状态机 |
| 仪器层 | `instruments/` | SCPI 读写、量程校验、统一资源管理 |
| 分析层 | `analysis/` | 指标公式、数据质量、统计分析 |
| 存储层 | `storage/` | JSONL/CSV 运行目录、SQLite 历史 |
| 报告层 | `reports/` | JSON/CSV 与离线综合 HTML 报告 |
| 基础设施 | `core/paths.py` | 统一项目路径与环境变量 |

## 4. 核心功能

1. **虚拟仪器**：PSU、DMM、电子负载，YAML 定义，SCPI 封装，量程校验。
2. **行为模型**：输入 9–16 V、输出 5 V、2 A、0.02 Ω、预设效率 0.90；
   六态保护状态机；非 NORMAL 输出为 0、效率不可定义。
3. **数据桥接**：显式读取 PSU/ELoad 设置并调用模型，再叠加 DMM 噪声；
   区分 `behavioral_model` 与 `static_mock`。
4. **自动化测试**：YAML 用例 015+、方案（SMOKE/REGRESSION/SUITE005）、
   设置值回读校验、四态判定、清理失败强制停止、退出码 0/1/2/3。
5. **故障与可靠性**：F001–F009 确定性故障、异常分类、有限重试白名单、
   清理验证、事件落盘、恢复率统计、实验预期固定。
6. **Web 平台**：六页、真实进度、进程级任务锁、状态缓存、刷新不重复执行、
   历史筛选与详情、CSV/JSON/HTML 导出。
7. **综合报告**：离线 HTML、A4 打印、无 CDN、从 SQLite + 配置快照生成、
   不覆盖、不重跑。
8. **工程化**：统一路径、requirements/environment/pyproject、ruff、
   coverage 84%、Windows/Linux 脚本、Docker 配置、备份脚本、CI 配置、
   发布验收脚本。

## 6. 模拟环境声明

- 所有仪器均为 PyVISA-sim 虚拟设备；
- 所有测量值来自模型或固定模拟响应；
- 当前没有真实硬件、没有真实芯片测试；
- 项目的价值在于测试架构、工程方法与可追溯性，不在于硬件指标本身。
